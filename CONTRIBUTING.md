# Contribuir

1. Crear una rama con propósito concreto (`feat/`, `fix/`, `docs/`).
2. Mantener cambios pequeños; explicar problema, comportamiento y validación.
3. Añadir migración cuando cambie el esquema; revisar el SQL generado.
4. Regenerar contratos cuando cambie la API y versionar lockfiles al actualizar dependencias.
5. Ejecutar las verificaciones del README antes de abrir un pull request.

No subir credenciales, datos personales, imágenes satelitales ni modelos pesados.
Los notebooks exploran; la lógica que produce resultados publicados vive en
módulos probados y ejecuciones reproducibles. Nunca agregar cifras ficticias
como resultados reales para completar una pantalla.

Antes de incorporar una nueva fuente registrar origen, producto/versión, licencia,
unidades, resolución, cobertura, limitaciones y acceso reproducible.

Convención de commits sugerida: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
La licencia de distribución debe acordarse con el equipo propietario.
